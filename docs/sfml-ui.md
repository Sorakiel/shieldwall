# Графический вид SFML

Ветка: `feature/ui-sfml`. Исходная база: `main`, коммит `2b71166`.

## Запуск

```text
cmake -S . -B build
cmake --build build --config Release
```

С Visual Studio запускается `build/Release/shieldwall.exe`; с Ninja —
`build/shieldwall.exe`. Зависимости загружает CMake через `FetchContent`.
Для сборки нужен компилятор C++17, CMake 3.24+ и интернет при первой настройке.
На Windows дополнительные пакеты SFML/FreeType не требуются. На Linux также
нужны системные заголовки оконной системы и OpenGL, перечисленные в
[инструкции SFML](https://www.sfml-dev.org/tutorials/3.0/getting-started/cmake/).

Данные и шрифт автоматически копируются рядом с executable. Если передан свой
путь к каталогу юнитов, используется именно он. Исходные файлы в `data/`
после изменения нужно заново скопировать сборкой, чтобы обновить копию у executable.

## Управление

- Ввод бюджета и seed: цифры, Backspace, Ctrl+A, Enter или «Продолжить».
- «К бою»: первый ход выбранных армий.
- «Следующий ход» / пробел: один следующий полный ход.
- «Автобой» / A: включить или приостановить автоматическое продолжение.
- Стрелки возле названия команды / колесо над армией: следующие пять бойцов.
- Колесо над журналом: история сообщений; в памяти остаются последние 5000 строк.
- После результата: «Новая партия» или «Выход».
- Esc или крестик окна: выход, в том числе во время ожидания следующего хода.

Размещение масштабируется при изменении размера окна с сохранением пропорций.
Номер позиции сохраняется при пролистывании. Рамка обозначает команду,
цвет шапки и подпись — тип юнита. HP берётся из модели без пересчёта урона.

## Граница между видом и логикой

`View` описывает ввод, меню и отображение. `ConsoleView` содержит прежний
текстовый вывод; `SfmlView` — окно и его события. `ConsoleUI` сохраняет прежний
публичный интерфейс для `BattleRunner` и передаёт виду:

- копии состояния армий (`BattleSnapshot`), без указателей на уничтожаемых юнитов;
- строки, уже сформированные существующим `EventFormatter`;
- результат боя, полученный от runner.

`Menu` явно сообщает виду этапы `Setup`, `Recruitment`, `Battle`, `Result`.
Во время боя `SfmlView::showArmies` показывает результат хода и ждёт следующего
нажатия либо таймера автобоя. Пока метод не вернулся, существующий синхронный
`BattleRunner` не вызывает следующий `nextTurn()`. После поражения армии
ожидание пропускается, чтобы результат появился сразу.

Закрытие окна бросает `ViewClosed`; `main` завершает программу с кодом 0.
Других потоков нет, поэтому окно и модель не обращаются к удалённым юнитам
одновременно. `BattleRunner.*`, `EventFormatter.*`, ядро боя, файлы данных
и общие заголовки не изменяются.

## Проверка

```text
cmake -S tests/ui -B build/ui-tests
cmake --build build/ui-tests --config Release
ctest --test-dir build/ui-tests -C Release --output-on-failure
```

Тесты не требуют окна и не загружают SFML. Они проверяют прежнее меню/форматтер,
передачу этапов новому виду, сохранность снимков после удаления юнита, точную
передачу текста и прерывание runner после одного хода при закрытии вида.
Запускается также существующий набор тестов данных.

В текущем `main` ядро всё ещё заменено `tests/stubs/`: журнал обычного боя содержит
границы ходов и итог, но не события ударов. `--demo-view` показывает все семь типов
заданных событий. Этот режим не имитирует полноценное ядро и не изменяет правила боя.
