# Shieldwall

Консольный автобой двух армий на C++17. Задаёшь лимит цены и seed, программа
случайно набирает две армии (лёгкие, тяжёлые, лучники) и прогоняет бой по ходам с журналом.

Лабораторная по проектированию программной архитектуры, делаем втроём.

## Как запустить

Из корня репозитория:

```bash
cmake -B build
cmake --build build
./build/shieldwall
```

Программа читает `data/units.txt` относительно текущей папки, поэтому запускать надо из корня.
Ввод: лимит цены (например `40`), seed (например `42`), затем `1` — «К бою».
`./build/shieldwall --demo-log` печатает пример журнала на заготовленных событиях.

На Windows с MSVC кириллица в исходниках читается благодаря флагу `/utf-8`, он уже включён в
`CMakeLists.txt`. Консоль переключается на UTF-8 автоматически.

## Что сейчас работает, а что нет

- Работает: файл с характеристиками юнитов, генерация армий по лимиту цены, ручная закупка (логика в `ArmyBuilder`, экрана в меню пока нет), меню,
  вывод строёв и журнала, сохранения (код есть, в меню пока не подключены).
- Не готово: само ядро боя (`Unit.cpp`, `Army.cpp`, `BattleEngine.cpp`). Пока вместо него
  стоят заглушки из `tests/stubs/`, поэтому бой идёт без настоящих правил и без строк ударов
  в журнале. Когда ядро будет влито, три строки с заглушками в `CMakeLists.txt` нужно удалить.

## Данные юнитов

`data/units.txt` — по строке на тип: `тип;hp;с руки;выстрел;дальность;защита;цена`.
Первая строка `version;1`, строки с `#` и пустые игнорируются. Характеристики правятся без
перекомпиляции. Если файл битый, программа пишет, в какой строке ошибка.

## Сохранения

Сохраняемся в начале каждой фазы (закупка, бой, результат) и после каждого хода, первое
сохранение делается сразу после закупки. В файле лежат фаза, лимит цены, seed боя, номер хода
и стартовые составы обеих армий. Состояние боя не хранится: он проигрывается заново с тем же seed
до нужного хода, поэтому файл маленький. Это работает, только если вся случайность боя идёт
через один `mt19937` внутри движка.

- Записать: `SaveService::saveToFile(data, "saves/autosave.txt")` (папка создаётся сама).
- Открыть: `SaveService::loadFromFile`; для боя `BattleReplay::replay(data)`, для закупки
  `ArmyBuilder::restore(...)`.
- Составы нужно снять **до первого хода** (`SaveService::snapshot` или `ArmyBuilder::units()`):
  после боя у юнитов уже нет стартового hp.

## Тесты

```bash
sh tests/run_data_tests.sh
```

Проверяет файл данных, генерацию армий, сохранения и воспроизведение боя. Пока ядра нет,
подставляет заглушки, потом сам перейдёт на настоящие классы. Тесты оболочки лежат в `tests/ui`
(`cmake -S tests/ui -B build/ui-tests && cmake --build build/ui-tests && ctest --test-dir build/ui-tests`).

## Кто что делает

| Часть | Кто | Файлы |
|---|---|---|
| Ядро боя | Ксюша | `Unit.cpp`, `Army.cpp`, `BattleEngine.cpp`, `TargetSelector.*` |
| Армии и данные | Никита | `data/units.txt`, `UnitCatalog.*`, `UnitFactory.*`, `ArmyGenerator.*`, `ArmyBuilder.*`, `SaveService.*`, `BattleReplay.*` |
| Оболочка и логи | Коля | `EventFormatter.*`, `ConsoleUI.*`, `Menu.*`, `BattleRunner.*`, `main.cpp` |

Общие заголовки `Unit.h`, `Army.h`, `BattleEngine.h`, `Event.h` не меняем без согласования в чате,
правка — отдельным коммитом.

## Как работаем

- В `main` напрямую не коммитим, только через PR с одним апрувом. `main` должен собираться.
- Ветки латиницей, строчными, через дефис: `feature/...`, `fix/...`. Каждое утро `git pull --rebase origin main`.
- Свои файлы в `CMakeLists.txt` дописываем в конец списка.
- Коммиты с префиксом: `core:`, `data:`, `ui:`, `fix:`, `build:`, `docs:`, затем короткое описание без точки.
- Стиль: `#pragma once`, отступ 4 пробела, классы `PascalCase`, методы `camelCase`, поля `hp_`.
- Случайность только через `std::mt19937` с seed, `rand()` не используем: иначе бой нельзя воспроизвести.
